# 本机编译适配（1.5.8）

启动器携带插件原生源码、构建模板和验证脚本，无需另外安装 Python。它使用你选择的 UE 开发文件，为该构建编译插件预览组件。

## 使用步骤

1. 完整解压 `VFXMeshLauncher-1.5.8-Windows.zip`，保留全部文件夹。
2. 选择 `.uproject`；启动器自动查找引擎，必要时从候选列表选择。也可选择或粘贴本机 `UnrealEditor.exe`。
3. 选择变化后会自动检测，并提前检查开发文件、MSVC 与 Windows SDK。通过时直接安装；缺少组件时点“一键编译并继续安装”，确认后开始。
4. 自动编译并在独立空工程验证预览、材质和重复开关。界面显示阶段与耗时，可取消；进程超时会停止本次子进程。编译日志可随时打开。
5. 验证通过后直接显示目标工程安装确认。确认后安装，原生组件变化时请先保存并关闭对应工程。取消安装会保留已验证的结果，稍后可继续。

## 1.5.8 自动补齐与验证编译环境（2026-10-14）

- 需要编译时，按所选 UE 的 Windows_SDK.json 检查完整 MSVC、Windows SDK、引擎开发文件和配套 .NET，排除被 UE 禁用的编译器版本。
- 缺少支持的 C++ / SDK 组件时，点击 **补齐环境并继续编译**。启动器从微软官网下载、验证数字签名，并为官方安装器选好缺失组件；已有可用环境不会重复安装。
- 微软窗口的许可、安装确认和 Windows 管理员授权需要本人完成。安装结束并关闭安装器后自动复查，执行一次真正的 C++ 编译链接测试，再继续插件编译、独立验证和目标工程安装确认。
- 下载最多重试三次；取消授权、安装器占用、空间不足、需要重启、组件仍不完整均显示具体下一步。不会强制关闭系统安装器、自动重启或无限循环重试。再次打开会保留工程和引擎选择。
- 缺少公司引擎专用头文件、导入库、规则或配套 .NET 时，需补齐同构建开发包；微软 C++ 安装器不能替代这些文件。未知版本要求不会盲装。

完整更新启动器本身，保留所有附带文件夹。此版本环境安装会增加系统开发组件，但不会改写工程关联、全局 BuildConfiguration.xml、引擎文件或无关项目资产。



编译本身不安装到你的工程。安装会备份旧插件，只处理该工程的 `Plugins/VFXMeshGenerator` 和 `Saved/VFXMeshGenerator`。项目描述文件、Content、Config 和其他插件不在安装写入范围。

## 需要什么

- 所选 UE 的完整 C++ 开发文件：UnrealBuildTool、配套 .NET、编译规则、头文件、生成头文件、导入库。
- Visual Studio / Build Tools 的 C++ 开发工作负载、MSVC x64/x86 工具集和 Windows SDK。具体版本由该引擎的 UBT 选择，不固定到此电脑的编译器版本。
- 缓存磁盘至少 2 GB 空间。首次编辑器着色器缓存可能额外占用空间。

参照 [Epic 官方开发环境配置](https://dev.epicgames.com/documentation/en-us/unreal-engine/setting-up-visual-studio-development-environment-for-cplusplus-projects-in-unreal-engine)。公司定制引擎需要使用公司提供的同构建开发包。

## 失败时怎么处理

| 提示 | 处理方法 |
| --- | --- |
| 没有 MSVC / Windows SDK | 在 Visual Studio Installer 中补齐 C++ 工作负载；按 UBT 日志要求安装版本。 |
| 缺少头文件、导入库或 .NET | 补齐所选 UE 的开发文件；不要拿另一版本的 SDK 混用。 |
| `DerivedDataCache` / `UE5Rules` 模块规则缺失 | 启动器先用当前引擎的规则源码在独立缓存重建副本，仅供本次构建进程使用；不替换引擎规则库。若源码或配套 .NET SDK 缺失，请向维护者补齐同构建开发包。 |
| C++ API 编译错误 | 点击“查看编译日志”，提供 `compile.log`；该构建可能需要额外源码适配。 |
| 组件编译成功，验证失败 | 提供 `verify-editor.log` 和验证结果；此结果不会进入可安装缓存。 |
| 引擎在编译过程中变化 | 等引擎同步结束，再重新编译。 |

日志保存在 `%LOCALAPPDATA%/VFXMeshLauncher/NativeBuilds/work-*`，不会自动上传。日志可能包含本机路径，共享前可以检查。退出编译后可手动删除旧的 `work-*` 工作目录；保留校验通过的缓存目录才能复用适配结果。

## 兼容性边界

适配使用具体 UE 版本、构建号和全部链接模块的 DLL 指纹，盘符不参与匹配。相同 BuildId 的不同补丁不会混用组件。原始下载包始终按发布 SHA-256 校验，本机派生包另有验证记录和校验值。

每个适配结果只对应生成它的插件包与引擎文件。更换插件版本或更新引擎后需要重新检测，必要时重新编译。编译成功不等于所有插件功能都已穷尽验证，保存资产仍需在工具中确认。
