# 维护者发布流程

普通使用者只需启动器，不需要执行这些命令。

1. 修改源码，将 `version.json` 中两个版本、`Launcher/version.py` 的 VERSION、插件 `.uplugin` 的 VersionName 同步升级。Version 使用递增整数。当前构建工具要求插件与启动器版本相同。
2. 在 Windows x64 上安装 Python 3.14 与 `pip install pyinstaller==6.22.3`。
3. 从仓库根目录运行 `python -m unittest discover -s tests -v`。在实际 UE 5.8 工程中验证修改；涉及资源时验证冷启动，脚本修改还应验证热重载与未保存参数保留。
4. 运行 `python scripts/build_release.py`。产物位于 `release/版本/`。
5. 提交并推送源码。在 GitHub 创建 **草稿发行版**，标签格式必须为 `vfx-v1.4.0`（替换实际版本），指向已验证的提交。
6. 上传该目录的插件 ZIP、启动器 ZIP、`vfx-manifest.json`、`SHA256SUMS.txt`。清单使用这些正式下载地址与校验值，不能手工混用不同次构建的文件。
7. 检查版本、大小、SHA-256，填写更新说明，然后发布正式发行版。全部文件就绪后再公开；启动器忽略草稿和预发行版。
8. 重新打开旧启动器确认发现新版本，实际下载、更新与回退各验证一次。若改了热更新连接组件或 `.uasset`，启动器应提示关闭工程。

下载接口通过 GitHub Releases REST API 获取带 `vfx-v` 标签的正式版本及 `vfx-manifest.json`。用户不需要 GitHub 账号或访问令牌。不要将令牌、个人工程、生成模型、缓存或本机设置提交到仓库。

清单中的 `minimum_launcher` 指定能安装此插件包的最低启动器版本。1.2.0 增加原生组件的引擎指纹检查，1.4.0 插件的最低启动器仍为 1.2.0。更旧的启动器应先完成自身升级。

## 原生预览组件

工作台将 `SEditorViewport` 和 `FAdvancedPreviewScene` 放入 `NativeWidgetHost`。小型适配 DLL 通过 C 导出函数连接 Python，只在编辑器主线程操作。预览组件按 BuildId 放在 `Plugin/VFXMeshGenerator/Native/Win64` 下，清单同时记录引擎 DLL 和适配 DLL 的 SHA-256；启动器与运行时都会校验。

需要匹配版本的 UE 头文件、生成文件、导入库和 Visual Studio C++ 工具链。示例（替换为实际路径）：

```powershell
python scripts/build_native.py --engine 'D:/UE/Engine' --sdk 'D:/UE/Engine' --vcvars 'C:/Program Files (x86)/Microsoft Visual Studio/18/BuildTools/VC/Auxiliary/Build/vcvars64.bat'
```

`--engine` 是目标引擎目录，`--sdk` 提供构建资料；定制引擎应优先使用自己的完整 SDK。脚本用临时 CompilerHost 生成编译响应文件，再构建适配 DLL。可用 `--configuration-dir` 复用响应文件目录。当前脚本选择 MSVC 14.50。

每个新引擎构建都必须冷启动验证：视口加载、鼠标旋转/平移/缩放、用户材质、关闭/重开工作台、保存隔离。不能仅改 BuildId 或指纹使未验证二进制通过检查。原生 DLL 变化需要关闭 UE 后更新。

`tests/ue_workspace_verify.py` 只允许在指定的 `vfx120` / `vfx130` 独立测试项目运行。`tests/ue_material_verify.py` 仅允许在 `vfx130-stock`、`vfx130-native` 运行。它们会创建测试资产并用确定的确认结果测试取消与确认保存；不要在真实工作工程运行。
